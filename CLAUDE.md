# CLAUDE.md

Chef-bnb: a NYC dinner-party marketplace (Next.js App Router, TypeScript, Tailwind, Prisma + Neon, Auth.js). Read `docs/implementation-guide.md` for the build order and `docs/strategy.md` for the spec (Data model, Booking model, Engineering design). Where they conflict, ask rather than guess.

## Commands

```sh
pnpm db:local     # embedded Postgres on :54329 for dev + tests (data in .local/pg); .env.local points at it
pnpm dev          # dev server
pnpm verify       # lint + typecheck + vitest + build — must pass before any PR
pnpm test         # vitest only (src/**/*.test.ts)
pnpm db:migrate   # prisma migrate dev
pnpm db:seed      # tsx prisma/seed.ts
```

## Rules that matter here

- Next.js 16 with `cacheComponents` on: APIs differ from older versions. Check `node_modules/next/dist/docs/` before using an unfamiliar API. No `runtime` segment exports.
- Prisma 7: connection URLs live in `prisma.config.ts`, not the schema. Client is generated to `src/generated/prisma` (gitignored); run `pnpm db:generate` after schema changes. Runtime uses `DATABASE_URL` (pooled) via `@prisma/adapter-pg` (`getDb()` in `src/lib/db.ts`); migrations use `DIRECT_URL`. CHECK constraints (max_guests ≤ 10 etc.) are hand-written in the migration SQL — keep them when adding migrations.
- All mutations are server actions or route handlers validated with zod. Booking writes go through `src/lib/bookings/` (`requestSeats` locks the event with `SELECT ... FOR UPDATE`; `decideSeatRequest` holds the pure rules; `transitions.ts` is the state machine), and every state change writes a `booking_log` row in the same transaction.
- Auth: Auth.js v5, JWT sessions. `src/auth.config.ts` is DB-free and shared with `src/proxy.ts`; `src/auth.ts` adds the providers and a lazily-created Prisma adapter (never touch the DB at import time — CI builds without `DATABASE_URL`). Primary sign-in is phone + texted code: `startPhoneSignIn` sends through `getVerifier()` (`src/lib/sms/verify.ts`: Twilio Verify when `TWILIO_*` is set, else a console verifier that accepts `000000` outside production) and parks the number in a short-lived cookie; `verifyPhoneSignIn` calls the `phone` Credentials provider, which finds or creates the user by `users.phone`. `users.email` is nullable (CHECK: email or phone); chefs get an email on the application (`claimEmail`). The proxy sends nameless users to `/signin/name` on GET; `setNameAction` refreshes the JWT with `updateSession`. Numbers are E.164 via `src/lib/auth/phone.ts`; display with `displayName`/`contactLine` in `src/lib/contact.ts`, never raw `user.email`. The dev email sign-in (`src/lib/auth/dev-login.ts`) stays for seeded accounts outside production. Session reads (`getCurrentUser`, `requireUser`, `requireRole`) must sit inside `<Suspense>`; a `redirect()` from inside a streamed boundary returns HTTP 200 with a client redirect, so hard gates also live in the proxy.
- Tests: `src/**/*.test.ts` are pure unit tests; `src/**/*.db.test.ts` need `TEST_DATABASE_URL` pointing at a migrated Postgres and skip otherwise. CI provisions Postgres and migrates it before verification. The db files run one at a time (vitest `db` project, `fileParallelism: false`) because they share a database and the jobs sweep scans all of it; keep new db tests cleaning up in `afterAll`. Locally, `pnpm db:local` plus the URLs in `.env.local` (vitest and the Prisma CLI both load it) run them against the embedded `chef_bnb_test` database; never point these tests at production. The Prisma CLI needs Node >= 22.12 (`.nvmrc`).
- Visual walkthroughs: a puppeteer-core script driving the installed Chrome (`walk.mjs` in the session scratchpad; recreate if needed) signs in as guest / chef / admin, exercises each flow and screenshots at 1280 and 390 px. Headless Chrome prefers dark mode, so screenshots double as a dark-theme check. A viewport change can reload the page; wait for network idle before typing.
- Private columns (exact address, payment handle, guest emails) are only selected in server functions that check role and booking status. Public pages query ONLY through the select lists in `src/lib/queries/public-select.ts` (`PUBLIC_*_SELECT`); a unit test rejects any private column there. Keep it that way when adding fields.
- Security: `src/lib/security/`. `rateLimit` is a fixed-window counter in the `rate_limits` table (one atomic upsert; keys like `signin:ip:<ip>`, `book:user:<id>`); every mutating server action calls `rateLimitMessage` with a rule from `limits.ts` before doing work, and `devSignIn` limits per IP and per email. Headers come from `securityHeaders()` via `next.config.ts` (CSP allows Mapbox and, on previews only, Vercel's toolbar). `hardenConnectionString` in `src/lib/db.ts` forces TLS off-localhost. Per-guest booking caps live in `requestSeats`. Keep new mutations behind a rate limit and new hosts in the CSP.
- Legal pages: `/terms` and `/privacy` render `LegalPage` (`src/components/legal.tsx`) from section arrays. House rules live in `src/lib/policies.ts`, derived from `RULES`; reuse `HOUSE_RULES` / `HOUSE_RULES_SHORT` anywhere the policy is stated rather than retyping numbers. Bump `POLICIES_UPDATED` in `src/lib/site.ts` when the text changes. `NEXT_PUBLIC_SUPPORT_EMAIL` is the contact address on both pages.
- Reviews: rules in `src/lib/reviews/reviews.ts` (`reviewEligibility` is pure; `createReview` relies on the unique index on `booking_id`). Public pages read reviews only through `PUBLIC_REVIEW_SELECT` (no author); `/admin/reviews` is the one place the author shows.
- Notifications + jobs: senders in `src/lib/email/notify.ts` take a `Messenger` (`src/lib/messaging.ts`: `{ email: Mailer, sms: SmsSender }`, `getMessenger()`) and route through `deliver()`: text when the recipient has a phone, else email (`prefer: "email"` for long ones like the chef decision). Email templates in `src/lib/email/templates/` (React Email, `{ subject, react }`); text versions in `src/lib/sms/texts.ts` built from the same props, so add both when adding a notification. Resend / Twilio Messages when configured, console otherwise, memory transports in tests. Senders run after the transaction commits and never throw. The five scheduled jobs live in `src/lib/jobs/` (`runJobs`), reached by `/api/cron` (Bearer `CRON_SECRET`) and the admin "run jobs now" button; each is idempotent through its marker column, and `notifyAddressReveal` is the only path that sends a venue address to a guest. Vercel Hobby allows daily cron only, so `vercel.json` runs at 13:00 UTC. `POST /api/admin/seed` (same bearer, only while `DEMO_SEED=true`) wipes and reloads the demo data from `prisma/seed.ts` (`seedDemo`); turn the flag off before real content.
- Cache Components gotchas met so far: a component that uses `new Date()` before any request API must `await connection()` first (home page); `redirect()`/`notFound()` inside a streamed `<Suspense>` returns HTTP 200 (Next injects `noindex`; this is documented behavior), so hard gates belong in `src/proxy.ts`.
- Visual checks: headless Chrome's CLI `--window-size` can't go below ~500px on macOS; use CDP device emulation for phone widths (a `shot.mjs` driver lived in the session scratchpad — recreate if needed).
- Discovery: `/events` defaults to the calendar; `parseEventFilters` reads one `where` param that is a borough code or a neighborhood from `src/lib/nyc/neighborhoods.ts` (`NeighborhoodSelect` is the shared dropdown; venues derive borough from neighborhood). `/events/past` lists COMPLETED dinners through `PUBLIC_PAST_EVENT_SELECT`. `events.photo_urls` are public; stock placeholders in the seed come from images.unsplash.com (allowed in `next.config.ts` images and the CSP).
- Brand: follow the Covers brand guide (Claude artifact 1wAuDWDSGU2JC3jEb74pH7). Headlines and the lowercase wordmark in Newsreader (`font-display`; Instrument Serif was the guide's pick but read too tall), body in Geist, every date/place/count/price in Geist Mono (`font-mono`); tokens in `globals.css` (paper, paper-2, surface, ink, muted, line, terracotta, night). Voice: rule then reason, specifics over adjectives, second person; never "curated", "culinary", "elevated", "bespoke", "foodie", "experience" (noun), "unlock", "discover", "community" (noun). One terracotta button per screen; the CTA is "Save my seat". Site photography (hero, host, mood strip) lives in `src/lib/brand-photos.ts`; chef header + portrait are `chef_profiles.photo_urls[0..1]`. All stock placeholders until the Covers shoot: swap URLs, keep keys.
- Money is integer cents. Timestamps are UTC, displayed in America/New_York.
- One milestone per PR, each leaving `main` deployable. Spec questions go to the strategy's Open questions, not into invented behavior.
